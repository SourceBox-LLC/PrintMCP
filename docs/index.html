Features

Built for the whole pipeline,
not just one step.

Search → download → slice → print, without ever leaving your AI assistant.

One server, the whole pipeline

Search → download → slice → print, without leaving your assistant. PrintMCP covers all three stages in a single MCP server.

License-aware sourcing

Every model's license is surfaced before you download, so you never misuse a file. Know whether it's CC, non-commercial, or restricted upfront.

Real slicing, real estimates

Drives the same CuraEngine that Ultimaker Cura ships, and reports the true print time and filament usage straight from the engine.

Safe by default

Tools that physically actuate the printer — heaters, motors, starting prints — refuse to act unless you explicitly pass confirm=true.

Structured or human output

Every tool accepts response_format — markdown for readable replies, json for programmatic use. Your agent picks what it needs.

Independent levels

Use Level 1 with just a Thingiverse token. Add Cura later for slicing. Wire up OctoPrint whenever your printer is ready. Start small, grow as you go.

Safety Model

Your printer is safe
until you say go.

Level 3 drives a real machine. A bad tool call could heat a nozzle, move an axis, or abandon a print — so PrintMCP defaults to dry runs.

  • ✓
    Dry runs by default Every physical-actuation tool returns a harmless preview of what would happen — and sends nothing to the printer — unless you pass confirm=true.
  • ✓
    Temperature sanity checks The bed is capped at ~140 °C and other targets are range-checked, so a typo can't command a wild value.
  • ✓
    Read-only tools never need confirmation Checking status, listing files, and monitoring job progress are always safe — no confirm required.
  • ✓
    Credentials stay in .env Tokens and API keys live in a local .env file and are sent only to the services they belong to — never surfaced in tool output.

FAQ

Questions people ask.

The Model Context Protocol is an open standard that lets AI assistants call external tools. PrintMCP is an MCP server — it exposes 3D-printing tools (search, slice, print) that an AI agent like Claude can call on your behalf. You just chat; the agent does the work.
No. The levels are independent. You can use Level 1 with just a free Thingiverse token to search and download models, and add Cura for slicing later. Wire up OctoPrint whenever your printer is ready — the server works fine without it.
Any client that supports the MCP standard: Claude Desktop, Claude Code, Cursor, Windsurf, opencode, and others. The included setup script (scripts/setup-mcp.sh or setup-mcp.ps1) auto-detects your installed clients and configures them for you.
Every tool that physically actuates the printer — heating, moving axes, starting a print — defaults to a dry run. Called without confirm=true, it describes what would happen and sends nothing to the printer. You (or your agent, with your go-ahead) must explicitly pass confirm=true to actually act. Read-only tools like checking status never need confirmation. Temperatures are also sanity-checked so a typo can't command a wild value.
Yes — free and open source under the Apache License 2.0. No paid tiers, no premium version. The code is on GitHub for anyone to inspect, modify, and contribute to.
Models on Thingiverse carry their own licenses (often Creative Commons; some are non-commercial). PrintMCP surfaces each model's license before you download via thingiverse_get_model — so you can respect it before reusing, remixing, or selling a print. PrintMCP's own code is Apache 2.0; the models and third-party tools (Cura, OctoPrint) carry their own licenses.
More print backends (a Moonraker/Klipper backend for non-OctoPrint printers), more slicing depth (printer profiles, quality presets, CuraEngine warnings for oversized models), and more model sources (Printables, MyMiniFactory) behind a shared search interface. See the roadmap on GitHub.
